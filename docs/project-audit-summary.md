## 总体判定

项目无法在现状下直接复原上线。前端编译产物相对完整，真正的关键路径在遗失的后端、数据、微信平台资产和原始源工程。

| 优先级 | 问题 | 影响 |

## 架构复原

两端均是 uni-app/Vue 2 编译产物，采用 webpack 模块运行时、Vuex 状态和 uView 组件。请求基址在编译包中硬编码：

- 生产：`https://interface.mijingyueke.com/api`
- 测试：`https://test.mijingyueke.com/api`

两个基址当前均可建立 HTTPS 连接，根路径返回 404。通过微信开发者工具运行管理端后，生产接口 `POST /common/dict` 已实测返回 HTTP 200，响应包含 `uploadURL: https://static.mijingyueke.com/` 和默认课程、用户、员工、会员卡图片名。这证明旧生产后端至少公共字典服务仍在线，但仍不能证明登录、业务数据、支付和写接口完整可用。

接口全部使用 POST，载荷混用 JSON 与 `application/x-www-form-urlencoded`。会员端请求统一在 URL query 中加入 `deviceId`，登录后加入 `tokenId`。查询请求可发送 `dsname: slave`；写操作后的约两秒内查询被强制走主库，显示旧后端可能采用主从读写分离和短暂读后写一致性策略。

功能域可以稳定归纳为：身份权限、品牌/场馆、员工、课程/排课、会员/卡项、预约履约、订单支付、报表、提醒通知和系统配置。后端重建应围绕这些领域和状态机设计，再提供旧路径兼容层。

## 高置信真实缺陷

### 管理端遗失页面

以下两个目标被多个页面反复引用，但源码中不存在且未在 `app.json` 注册：

- `/pageReport/coach/privateDetail`
- `/pageReport/coach/leagueDelete`

自动扫描记录的 12 条无效导航均归并到这两个目标。需要根据调用参数和相邻页面重建，或确认原设计后改向现存详情页。

### 会员端缺陷

- 购卡停业校验逻辑把 `exists` 强制设为 `false`，可能绕过停业限制。
- 团课分享页绑定 `close` 但页面未实现对应处理器。
- 领卡页绑定 `moreProject` 但页面未实现对应处理器。
- 上传完成回调无条件执行 `JSON.parse`，失败路径还读取了错误变量，网络或非 JSON 响应会产生二次异常。
- 开发环境登录存在把字面量 `test` 当作 code 的路径，必须确认旧服务是否保留测试后门。

具体位置、上下文和影响见 `member-audit.md`。

### 安全与隐私风险

- `tokenId` 与 `deviceId` 位于 URL，可能进入代理、网关、监控和客户端日志。
- 生产请求拦截器输出配置日志，扩大令牌泄漏面。
- 已在 2026-07-11 使用测试 AppID运行会员端验证：生产 `POST /c/user/wxlogin` 接受字面量 `code=test`，返回有效会话、会员身份、场馆和客户端配置。该测试路径实际可用，属于必须立即关闭或限制来源的 P0 认证后门风险。
- 支付前端只依据 `requestPayment` 成功跳转；最终结果必须以后端回调验签为准。
- 无令牌分享/领卡接口必须有签名有效期、防重放、并发锁和权限边界。
- 手机号、会员信息、生日、消费与课程记录属于敏感个人信息，必须补齐最小化采集、授权说明、删除/导出与审计机制。
