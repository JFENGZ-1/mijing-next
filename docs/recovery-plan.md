# 项目复原与上线计划

## 目标定义

“复原上线”不是让首页在模拟器中出现，而是同时满足以下条件：

1. 两个小程序可编译、预览、真机启动。
2. 微信登录、手机号授权、角色/场馆切换可闭环。
3. 核心业务数据可创建、查询、修改并保持一致。
4. 会员约课、取消、候补、签到、扣课、退款状态可闭环。
5. 购卡/续费等支付链路可完成并可对账、退款、幂等处理。
6. 管理端权限、排课、会员卡、报表和通知可用。
7. 隐私合规、服务器域名、业务域名、支付与消息模板通过微信后台配置和审核。

## 已确认事实

- 两端均为 Vue/uni-app 编译到原生微信小程序的产物。
- 原始 `.vue`、依赖清单、构建配置、源码映射和后端代码均缺失。
- 会员端注册 35 个页面、386 个文件；管理端注册 150 个页面、1379 个文件。共 1765 个应用文件，页面四件套完整。
- 静态扫描提取到约 313 个跨端唯一接口路径，其中会员接口以 `/c/` 开头，管理接口以 `/b/` 开头，另有 `/wx/` 与 `/common/`。
- 请求统一追加 `deviceId`；登录后追加令牌。会员端字段名可确认是 `tokenId`，管理端使用独立 `token` 状态并需继续核验传输方式。
- 图片地址依赖后端字典返回的 `uploadURL`，因此静态资源服务也是后端重建的一部分。
- 管理端配置保留 AppID `wx144915b575a7792d`；会员端未保留可用 AppID。
- 微信开发者工具及 `wechatide` CLI 已安装并完成 `Codex` 授权；两端启动页 WXML/WXSS 均编译通过。管理端已运行至登录页；会员端真实 AppID 无权限，经用户许可临时使用测试 AppID 打开并验证首页。生产 `/common/dict` 返回 200，会员端生产 `/c/user/wxlogin` 还实测接受 `code=test` 并签发会话，必须作为 P0 安全问题处理。

## 第一性原理拆解

系统本质上由六个不可替代的能力组成：身份、租户/场馆、商品与权益、排课与预约、资金、统计与通知。页面只是这些能力的客户端投影。后端复原应先重建领域状态机和数据一致性，再逐个兼容旧接口；不能按页面数量机械创建 313 个互不相关的控制器。

建议领域边界：

| 领域 | 核心对象 |
|---|---|
| 身份与权限 | 微信账号、会员、员工、角色、权限、令牌、设备 |
| 场馆与组织 | 品牌、门店、营业时间、房间、员工归属 |
| 课程与排课 | 团课、私教课、教练、课程计划、停课、请假 |
| 会员与卡项 | 会员资料、会员卡、次数/余额、有效期、适用课程 |
| 预约履约 | 预约、候补、取消、签到、旷课、扣课、退款 |
| 交易与资金 | 订单、支付单、退款单、充值、消费流水、对账 |
| 报表与通知 | 收入、消课、排行、提醒、订阅消息、操作日志 |

## 分阶段执行

### P0：资产保全与可重复审计

- 保留当前编译产物原样，建立有效 Git 仓库并提交只读基线。
- 保存两端 AppID、主体、管理员、支付商户号、证书、域名、备案和云资源归属证明。
- 获取微信开发者工具并分别导入两个目录，记录所有编译告警。
- 对生产域名、数据库、对象存储、短信/消息服务和旧服务器做资产追踪。

完成标准：任何后续改动均可回退；所有已知资产有负责人和状态。

### P1：旧产物冒烟验证

- 补齐会员端测试 AppID，不直接覆盖生产配置。
- 验证启动页、登录页、首页、主要 tab 和所有分包可加载。
- 核验管理端主包实际上传大小；当前静态估算 2.016 MiB，存在超限风险。
- 逐条确认无效路由和缺失事件处理器是编译误报还是真缺陷。

完成标准：无后端时也能稳定进入预期的登录/空态页面，控制台无致命异常。

### P2：契约冻结与后端骨架

- 以 `generated/api-catalog.csv` 和 `generated/api-usages.csv` 建立接口兼容清单。
- 从每个调用点提取请求字段、响应字段、枚举和页面状态转换。
- 先实现 `/common/const`、微信登录、场馆/用户基础信息、字典与上传地址。
- 统一定义错误码、鉴权失效、幂等键、分页、金额单位和时间格式。

完成标准：两个客户端能登录并获取公共字典、用户、场馆和权限。

### P3：核心业务闭环

按依赖顺序实现：场馆/员工/课程 -> 排课 -> 会员/卡项 -> 预约/签到/扣课 -> 订单/支付/退款 -> 报表/通知。

完成标准：至少一条团课和一条私教课从创建到履约、退款、报表全链路通过。

### P4：重建可维护前端源工程

- 新建受版本控制的 uni-app 工程，逐页迁移而非反编译后直接维护。
- 抽离 API 类型、领域模型、权限、路由守卫、主题和通用组件。
- 使用环境变量管理测试/生产基址，密钥仅保存在服务端。
- 为核心状态机增加单元、契约和端到端测试。

完成标准：可从源码稳定构建出微信小程序，旧编译产物仅作对照。

### P5：上线门禁

- 微信后台合法域名、隐私协议、用户隐私保护指引、类目和资质齐全。
- 支付回调验签、金额校验、幂等、退款和日对账通过。
- 生产数据库备份、迁移、监控、告警、审计日志和灾备演练完成。
- 灰度账号完成会员端与管理端关键路径验收。

## 当前阻断项

1. 后端与数据库缺失，现有客户端绝大多数功能无法独立运行。
2. 会员端 AppID 已确认为 `wxb72f22dbc5dfba4c`，但当前账号不是该小程序开发者；两个小程序的主体和完整权限归属仍未确认。
3. 支付商户号、API v3 密钥/证书、回调域名和历史订单数据未知。
4. 原始 uni-app 源工程缺失，无法可靠重新编译或升级依赖。
5. 管理端已完成初步模拟器验证，但尚未完成全页面、登录、真机和支付验证；会员端因开发者权限缺失尚未打开。
6. 管理端主包接近微信限制，必须实测并做分包/资源优化。
7. 接口域名可连接不等于旧服务、数据和鉴权仍可用。

## 必须向业务/前同事追索的资产

- 两个小程序 AppID、主体管理员和开发者权限。
- 微信支付商户号、证书、密钥、回调配置、历史交易与退款数据。
- 旧服务器、数据库、Redis、对象存储/CDN、DNS、SSL 和备案账号。
- 短信、订阅消息模板、客服、地图或其他第三方服务账号。
- 原始 Git 仓库、uni-app 工程、CI/CD、环境变量和设计稿。
- 数据字典、角色权限表、业务规则、价格/退款/扣课规则和隐私文本。

## 验收原则

任何接口仅返回“看起来正确”的假数据都不算复原。每个核心流程必须验证权限、并发、重复提交、超时重试、跨场馆隔离、金额精度、时间边界、状态回滚和审计可追溯性。
